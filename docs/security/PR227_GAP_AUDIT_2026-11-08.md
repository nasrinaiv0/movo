# MOVO — PR #227 Updated Security Gap Audit
**Date:** 2026-11-08 (Asia/Manila)  
**Scope:** GitHub PR #227 at `7c041a27`, production `main` at `57735ad5`, and read-only security checks of the live MOVO Supabase project.  
**Decision:** **DRAFT — DO NOT MERGE OR RELEASE NATIVE BUILDS YET.** This document identifies evidence and gaps; it is not a penetration test or security certification.

## Evidence and limitations
- Native security branch adds Keychain/Android Keystore secure storage for Supabase auth and phone-automation keys, write-before-delete legacy migration, Android backup denial and `FLAG_SECURE`, iOS app-switcher privacy cover, Android R8, and `security.txt`. Browser token storage is intentionally unchanged.
- Isolated Vercel Sandbox `movo-security-audit-pr227-20261108`, exact branch `7c041a27`: dependency install, TypeScript typecheck, **644/644 Jest tests in 113 suites**, and optimized CRA build all passed. These tests do not execute the native Keychain/Keystore on physical devices.
- PR-head GitHub Actions: Phase 1 CI **success** (run 42245136094); Android debug and unsigned R8 release compilation **success** (run 42245136225); latest iOS workflow (run 42245135999) **failure status with canceled job** — not evidence of a Swift compiler failure, but **no successful iOS build sign-off**.
- `main` is **34 commits ahead of PR #227** with four PR-only commits. Read-only `git merge-tree --write-tree HEAD FETCH_HEAD` returns conflicts in `src/App.js`, `docs/PR_PROGRESS.md`, and `docs/engineering/MASTER_CHANGE_LEDGER.md`. The branch is **not merge-ready** and needs a regression-preserving integration against current main.
- GitHub branch metadata reports `main` branch protection **disabled**. Do not infer required CI gates or approval restrictions are enforced.
- Live Supabase: 28/28 `public` tables have RLS enabled. Security Advisor returns **12 authenticated-executable `SECURITY DEFINER` functions** and **leaked-password protection disabled**. One intentionally deny-all RLS table has no policies (`movo_ai_upstream_conversations`); confirm that this is intentional and not part of a broken customer workflow.
- Read-only SQL inspection found `auth.uid`, `user_id`, and explicit `search_path` references in each of the 12 functions. Those patterns are positive evidence, **not proof** of ownership enforcement for every linked account, transaction, bill, allocation and descendant row. No two-user adversarial test was performed; no production records or settings were changed.

| SEC-227-01 | **P0 — release process** | Main branch is unprotected; branch conflicts with 34 newer main commits. | Protect `main` with required status checks and review, then integrate PR into current main without discarding newer UI, accounting, or safety code. Demonstrate clean merge and current-head CI. |
| SEC-227-02 | **P0 — authorization assurance** | 12 live authenticated-executable finance `SECURITY DEFINER` RPCs. Source mentions `auth.uid()` but cross-tenant safety is unproved. | On an isolated staging clone, run positive/negative tests for each function with **two independent users**, foreign account IDs and related row IDs, cross-user transfers, delete/reverse, idempotency-key reuse, and concurrency. Do not claim plaintext erasure is guaranteed today. |
| SEC-227-04 | **P1 — iOS build / hardware** | iOS CI job canceled; no verified native Swift compile or physical-device Keychain tests. | Rerun iOS simulator CI and perform signed install/upgrade on physical iPhone; validate token migration, first-login/refresh, biometric/device lock, logout, app-switcher masking, and foreground/background handling. |

| SEC-227-06 | **P1 — web session/XSS** | Website continues Supabase JavaScript-readable local storage; HttpOnly server sessions absent. | Threat-model BFF/server cookies, session rotation, SameSite and CSRF, CSP, XSS sinks, and cross-origin request enforcement before redesign. No claim that native vault protects web XSS. |
| SEC-227-07 | **P1 — OAuth/deep links** | `movo://auth-callback` custom scheme persists; HTTPS verified links absent. | Verify Apple Associated Domains and AASA, Android App Links/assetlinks signing SHA-256, redirect allowlist, PKCE and error paths, cancellation, replay, and malicious-app callback interception. | SEC-227-08 | **P1 — auth operations** | No verified remote session revocation, account MFA/passkeys, security login alerts or trusted device controls. | Implement/test session inventory and revoke-all, optional MFA/passkeys, sensitive-event notifications, refresh-token invalidation and reauthentication flows. |
| SEC-227-09 | **P1 — abuse protections** | Broad API and OTP throttling, uniform request schema validation and device attestation not evidenced end-to-end. | Test per-user/IP/token rate limits and idempotency on auth, import, automation and financial endpoints; add input schemas and threat-model device attestation with replay controls. |
| SEC-227-10 | **P2 — secrets/supply chain** | Branch protection off; automated secret/CodeQL review and continuous dependency monitoring not verified. | Enable protected reviews, secret scanning, code scanning and dependency updates; retain signed/tagged release evidence and incident-response procedures. |

## Recommended staged acceptance sequence
1. **Do not merge** the stale PR head. First protect main and prepare conflict-resolved integration without overwriting 34 newer commits. Re-run current-head tests.
2. Audit the twelve SECURITY DEFINER RPCs and complete two-user negative tests against a disposable staging database. Never use real production user data for an exploit experiment.
3. Correct or explicitly gate incomplete native credential scrubbing. Prove data migration and fail-closed behavior on real upgraded devices.
4. Obtain iOS simulator success, verify signed iPhone and Android builds, then verified OAuth links and device-specific privacy behavior.
5. Address web session, MFA/revocation, abuse controls and store/security/legal sign-offs before claiming commercial readiness.
