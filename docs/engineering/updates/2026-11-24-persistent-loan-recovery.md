# Persistent loan request recovery — staging only

## Design before implementation
Stack on #343 at db2445cb72677a4ca75c4fd93224e94024d198d7. Reserve one immutable canonical request per authenticated owner in a dedicated IndexedDB store, using existing financeVault XChaCha20-Poly1305 with owner-bound AAD and an atomic readwrite transaction. Persist before network dispatch, keep ciphertext after ambiguous or failed replies, use the exact saved RPC payload and UUID on explicit user retry, and clear only after validated owner-bound acknowledgement. A different draft cannot replace a pending request. A read/decrypt/storage failure must fail closed. Add vault key-loss detection for this store and account/financial erasure cleanup. No automatic upload or new accounting posting; no remote migration. No guarantee across cleared browser storage, new device or deleted encryption keys. The protected receipt in #343 remains the authoritative idempotency fence. Test reload, cross-tab reservation, tamper/owner isolation, storage failure and acknowledgement handling. UI presents pending amount/name/account and an explicit retry; no silent replay. Keep existing screen and localization conventions. Independent security/Claude review and actual signed-in/native acceptance remain required.
