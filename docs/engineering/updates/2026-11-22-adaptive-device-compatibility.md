# Adaptive device compatibility — 2026-11-22

The owner requests adaptable support for iPhone Duo, Samsung foldables and smartwatches, preserving MOVO's structure and financial behavior. The [initial audit](../../audits/2026-11-22-device-compatibility-audit.md) records the original gaps; this is the implementation and acceptance handover.

## Implementation

- Keep React/CRA, Supabase, Capacitor/UIKit, bundle/package IDs and the existing transaction writer. No accounting, billing verification, account ownership, migration, production setting or customer record changes.
- Add a read-only Android `MovoWindow` plugin using stable AndroidX WindowManager 1.5.1. It reports WebView-relative fold rectangles and view dimensions only. Observe foreground window changes and remove callbacks on pause/destruction. Existing R8 plugin preservation covers this annotated plugin.
- The shared layout hook accepts browser viewport segments or native geometry, validates and scales rectangles, and picks the largest unobstructed pane (reading order breaks ties). A separating hinge/tabletop fold keeps the same mounted app and open form inside that pane; continuous displays retain the full workspace. RAF updates, media-query/visual-viewport events, stale-snapshot protection, cleanup and old-binary fallbacks are included. Posture is never saved to an account.
- Preserve document scrolling for ordinary windows and use the pane's scroller for folded navigation/Back. Shared dialogs, navigation, chat input and notifications stay in that pane. Compact transaction date/time inputs wrap; segmented controls respond to the dialog width and support old-WebView fallbacks. The transaction dialog's accessible title now follows the selected language.
- Enable a universal iPhone/iPad target with portrait and landscape orientations. Keep the iOS 15 deployment minimum. The existing UIKit chrome switches between bottom navigation and a scrollable native rail, mirrors all sidebar actions including Add/Settings, follows app reading direction, retains disabled/setup/modal gates, and returns its actual bar/rail dimensions to CSS. System colors, accessibility settings and safe-area constraints remain active.
- Apple Watch uses semantic/scalable fonts and a wrapping action. Both watch companions reject duplicate in-flight requests and recover after a bounded handoff timeout without logging or retrying a financial write. Wear OS uses black app/launch backgrounds, a content-sized 48dp-or-larger action, an inset scroll viewport for round displays, swipe dismissal and rotary scrolling. Companion scope remains **Quick Log on phone**, with no watch-side records, balances, purchases or credentials.
- iOS CI chooses the newest installed stable Xcode and records the SDK. Add iPad simulator install/launch coverage. Explicit `require_duo` dispatch requires Xcode 27.1+ and a named Duo simulator; absence fails rather than substituting another phone. An older runner's green build does not certify Duo full-display or pose behavior.
- Add Wear OS native instrumentation/CI for small and large round profiles, normal and 2× font scale, action visibility/text bounds/touch size, screenshot evidence and recovery from an unavailable phone. Signed pairing and store distribution remain separate.
- Exclude Jest-only JavaScript from the production TypeScript program; all runtime tests still execute in Jest and production strict checking remains enabled. This avoids pulling test-only server dependency graphs into the browser build. The original-only App Store build now fails if CRA's type-check worker aborts even when CRA exits zero. A silent checker abort was observed and is not accepted as a successful strict build.
