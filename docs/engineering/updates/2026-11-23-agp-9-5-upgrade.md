# 2026-11-23 — Android Gradle Plugin 9.5.1 and Gradle 9.6.0

## Owner request

The owner shared the Play Console report for app bundle 24 (1.0). It showed:

- DEX optimization: High.
- Optimization: 84%. Obfuscation: 86%. Shrinking: 86%.
- R8 full mode, resource shrinking (including the optimized variant) and class repackaging all on.
- Play's note: "Upgrade to AGP version 9.0 to get the best performance."

The request: "Improve MOVO's optimization to 100%. Upgrade to AGP 9.5 version."

## Changes

- **Root build.** `android/build.gradle` moves AGP from 8.13.0 to **9.5.1**, the newest 9.5 release on the AGP release page as of 2026-11-23. The `clean` task now uses `tasks.register` with `layout.buildDirectory`, because Gradle 9 removed `Project.buildDir`.
- **Gradle wrapper.** 8.14.3 → **9.6.0**, the minimum and default Gradle for AGP 9.5. AGP 9.5 needs JDK 17+; CI uses Temurin 21. SDK Build Tools 36.0.0 is already installed in CI.
- **App module.** `aaptOptions` (removed in AGP 9) becomes `androidResources { ignoreAssetsPattern }`, with the same pattern.
- **Wear module.** The release build is now minified, resource-shrunk and optimized with `proguard-android-optimize.txt`. It was unminified before.
- **`gradle.properties`:**
  - The Gradle daemon heap goes up to 3 GB.
  - **`android.newDsl=false` and `android.builtInKotlin=false`.**
    - Capacitor 8.6 and its plugin modules still use the pre-AGP-9 DSL: `lintOptions`, and per-module `buildscript` blocks pinning AGP 8.13. The local-notifications plugin also applies the separate Kotlin plugin.
    - Remove both switches once Capacitor ships AGP 9 builds. AGP 10 drops `android.newDsl=false`.
  - **`android.r8.strictFullModeForKeepRules=false`.**
    - Capacitor's bridge and the bundled Cordova framework create plugin classes by reflection.
    - Under AGP 9's strict semantics, a third-party `-keep class X` rule no longer keeps the default constructor.
    - Keeping the AGP 8.13 semantics avoids a release-only crash that no unit test would catch.
  - **AGP 9 defaults kept on:**
    - optimized resource shrinking;
    - the ban on global options such as `-dontoptimize` in library consumer rules;
    - `proguard-android-optimize.txt` only;
    - unique package names;
    - compile-time R class.
- **Keep rules.** `android/app/proguard-rules.pro` is unchanged on purpose. The paired-emulator R8 workflow (`scripts/r8/experiment.py`) accepts only the approved rule set.

## Why the Play score cannot reach 100% in a Capacitor app

Play's percentages measure how much DEX code R8 may optimize, rename and remove. Capacitor finds plugins and their `@PluginMethod` methods by name at runtime. Its own consumer rules therefore include `-keep public class * extends com.getcapacitor.Plugin { *; }` and the Cordova `-keep public class * extends org.apache.cordova.*` rules. Every member of those classes must keep its name and shape, or the JavaScript bridge breaks. That kept code is the main reason the scores stay below 100%.

Removing those rules would make every native feature fail at runtime:

- App Lock and Face ID / fingerprint;
- secure storage;
- notifications;
- store purchases;
- the browser, preferences and the Android back button.

The upgrade brings AGP 9.5's newer R8 and stricter defaults. Bundle 25 will show the new scores; this PR does not claim a number.

## 2026-11-23 — CI emulator disappearance follow-up

The first PR #340 exact-head run passed AGP 9.5.1 native debug/authTest/release and Wear release builds, but the paired R8 experiment failed after the emulator process disappeared during the third **baseline** instrumentation (`offlineWalletLogoStyleAndSyntheticOAuthCallback`). Two preceding instrumentations emitted the required PASS markers. An earlier AGP 8.13 run (#335) had the same infrastructure failure, so this is not evidence the AGP 9.5 upgrade broke Android. The saved emulator diagnostics show the netsim device transport closing; the host still had approximately 14.9 GiB available memory and no confirmed app assertion crash.

The paired test workflow now allocates **4096 MiB to each disposable baseline and candidate AVD** instead of 2048 MiB. This is an isolated guest-memory hypothesis and does not suppress failures, relax assertions, alter the R8 rules, change the OS image, or touch any native app code. Baseline and candidate are configured identically. Exact-head successful full emulator acceptance is still required; the change alone is not a pass. If disappearance persists, inspect the new emulator crash/host logs and pursue emulator-version or graphics isolation separately.
