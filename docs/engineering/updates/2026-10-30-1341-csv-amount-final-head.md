- **PR:** [#43 — Synchronize finance balances and summaries from one ledger](https://github.com/nasrinaiv0/movo/pull/43).
- **Current exact PR head:** `d9adcfedb6a61affa79a9b83bcbc77375e6a5801` (documentation-only cleanup after the source/test changes); PR remains open, draft, and mergeable.
- **Previous monitoring head:** `66e092faa6f4bd614fee8285b3138650039baadf`. The new implementation delta adds strict amount parsing in `src/lib/csvImport.js` and regression cases in `src/lib/csvImport.test.js`; supporting docs were updated in the same PR.
- **Before:** the amount parser stripped currency symbols, commas, and whitespace indiscriminately, then passed the result to `Number()`. A malformed amount such as `1,2,3` could become `123`; scientific notation such as `1e3` could be accepted as `1000`; unsupported suffixes/formatting were not consistently rejected.
- **After:** `parseAmount()` first validates the complete value against a strict format: plain digits or correctly grouped thousands (for example `1,234.50`), optional supported leading symbol (`₱`, `$`, `€`, `£`), optional sign, and optional decimal fraction. Only after validation are grouping commas removed. Non-finite, zero/negative-after-normalization, and values at/above `1e17` are rejected. Invalid rows return a row-level error: “Amount must use a valid number format, such as 1234.50 or 1,234.50.” Transaction type continues to determine income/expense/transfer semantics; this parser does not perform currency conversion.
- **Regression coverage:** valid plain/grouped/symbol-prefixed examples remain accepted; malformed grouping, repeated decimals, scientific notation, and unsupported text are rejected. The existing CSV quote-validation coverage remains in place.
- **Rationale:** prevent a malformed bank-export amount from silently becoming a different ledger amount before import.
- **Dependencies/migrations:** no package manifest or lockfile change was made for this parser change. No database migration, schema, RLS/grant, Auth setting, production financial record, or secret changed.
- **Privacy/security:** parsing occurs in the client-side import flow before the existing import operation; this change adds no new upload, telemetry, or provider call. Authenticated cloud import and owner-scoped persistence remain unverified.
