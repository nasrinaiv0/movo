# 2026-11-09 — Short referral codes and per-platform download QR codes (PR #258)

## Owner request

"Improve the referral features using less code (6digits sample: M78038) or they can use a QR code to download the app. separate for android and ios."

## What changed

- **One short code per person.** `movo_plan_grants.referral_code` is now `M` + five digits (`M78038`), generated by
  `movo_new_referral_code()` from `gen_random_uuid()` bytes; after 40 collisions in a row it switches to five characters
  from `0-9A-Z` without I/O. A check constraint enforces `^M[0-9A-HJ-NP-Z]{5}$`. The migration rewrites existing
  24-character codes row by row (production has 3, none used for a referral yet).
- **Single-use 64-character invites removed.** `movo_referral_invites`, `movo_issue_invite`, `movo_claim_invite` and
  `/api/referrals/invite` are gone; `movo_referral_claims` no longer references an invite.
- **Linking a code.** `movo_claim_referral_code(user, code)` (service role only; `/api/referrals/claim`) links a verified
  account created in the last 7 days that has not been referred and has not bought a plan. The same rule creates the
  points claim (`movo_link_referral_claim`). The free month (`claim_movo_trial`) accepts the short code too and keeps
  an existing referral (`coalesce`), which fixes a later code-less claim clearing `referred_by`.
- **Guessing limit.** `movo_referral_lookup` records every attempt in `movo_referral_code_attempts` and refuses after
  10 an hour per account. It returns errors instead of raising, so the attempt row is not rolled back.
- **API.** `api/lib/referralCode.js` normalises codes for both routes. `/api/purchases/trial` accepts short codes and,
  until the migration is applied, the older 24-character codes. `/api/referrals/status` adds `referralCode`,
  `canClaim` and `pointsEnabled`. Challenge/activate stay closed unless `MOVO_REFERRAL_POINTS_ENABLED=true`.
- **Download QR codes.** `/api/download?platform=ios|android&ref=CODE` redirects to `MOVO_IOS_APP_STORE_URL` /
  `MOVO_ANDROID_STORE_URL` when they hold an exact App Store / Google Play address for MOVO, otherwise to `/` with the
  code. `src/index.tsx` keeps `?ref=` on the device (`movo.pendingReferral.v1`) and removes it from the address; the
  free-month panel and Refer MOVO fill it in. No store address is assumed: MOVO is not listed in either store yet.
- **Refer MOVO sheet.** One compact panel: code with Copy/Share (the share text includes both download links),
  progress toward the 10-subscriber reward, two QR codes (iPhone · App Store, Android · Google Play), points only when
  the server has them on, and the friend's-code field only when `canClaim`. All text is translated (11 languages).

## Tests

- `supabase/tests/referral_points.test.sql`: code format and conversion, generator, constraint, case/space input,
  single link, own/unknown/malformed codes, old/paid/unverified accounts, 10-an-hour limit and reset, trial with a code,
  trial after a link keeps it, wrong code during the trial leaves no trial and keeps the attempt, status fields,
  +5/+100/−100 ledger rules, and no client or anonymous access to any referral function or table. Breaking the attempt
  limit or the trial `coalesce` makes the suite fail.
- `src/lib/referrals.test.js`, `src/lib/referralApi.test.js`, `src/components/ReferralSheet.test.js`.
