# MOVO full product audit

**November 20, 2026 · Asia/Manila**

**Release recommendation:** Hold public expansion and paid launch.

**Audited production source:** `44f3ab4d4156a09f7c9618f8ac6c41e43b2f02b7`, the #325 merge.

Vercel production and GitHub main matched at the audit checkpoint. Home, Terms, Privacy, Security, the public account-deletion page and both billing-readiness endpoints returned HTTP 200. The Apple endpoint reported disabled and Google reported enabled. Production checks were read-only. Browser writes used synthetic data in an isolated build of the same source.

## Verified behavior and coverage

- Exact audited source passed the Node 26.13.1 production build, TypeScript, 251 suites and 1,626 tests. The suite covers cent rounding, transfer routing, principal versus interest, receivables, credit card double-counting, recurring cycles, restoration and sync retries.
- Chromium covered Home, Wallet, Transactions and Menu in light and dark at six viewport sizes, for 48 measurements. The measured screens fit without horizontal overflow and used bottom navigation or the desktop sidebar. Root utility controls measured 40×44 or 45×45 CSS px. Guest expense keypad targets were 44 px tall and Save was 50 px tall.
- A synthetic ₱100.25 cash account and ₱12.34 expense produced a ₱87.91 balance after a reload. The offline service worker cache reloaded while offline and opened Wallet.
- Guest Friends displayed an explicit sign-in gate. Source review found verified accounts, opt-in directory handles, membership checks, explicit summary preview and sharing, revoke and block. Production catalog denied direct user calls to the two internal Friends RPCs. Two-account invite, expiry, QR, pasted-link, share/revoke, block and OS share-sheet behavior still needs end-to-end evidence.
- Plan & Usage displayed reference monthly/annual prices of ₱99.00/₱950.40 for Pro and ₱149.00/₱1,430.40 for Pro+. Verify localized price and purchase amount from actual store products. Actual mic, audible TTS, OCR camera, notification and wearable behavior require physical devices.
- Android source targets API 36 with min SDK 24. iOS project targets 15.0 and watchOS 10.0. Verify effective signed-package and dependency requirements, store-installed auth, device permissions, safe areas, OS sharing and Android 16 KB compatibility. [Android page size guidance](https://developer.android.com/guide/practices/page-sizes)
- Public web returned CSP, HSTS and frame denial. In-app delete entry, public policy availability and current store labels are evidence inputs. Verify operator and DPO details, actual data retention, AI disclosures, Apple App Privacy, Play Data safety and Financial features declarations against the shipping app and applicable territories. This audit does not establish legal clearance across all markets. [Apple review guidelines](https://developer.apple.com/app-store/review/guidelines/) · [Google Play Financial features](https://support.google.com/googleplay/android-developer/answer/13849271) · [Google Play account deletion](https://support.google.com/googleplay/android-developer/answer/13327111) · [Philippine NPC](https://privacy.gov.ph/)

## Rollout order

1. Close accounting and account isolation on isolated staging. This protects balances and data boundaries. The trade-off is time to test migration order, older clients and recovery with unsynced data.
2. Close iOS launch, device sign-in and both store lifecycle gates. This confirms customers can retain and restore paid access. It requires signed packages, approved store test tracks and physical device time.
3. Land the keyboard and Reduce Motion fixes after exact-head checks. Reuse the existing panel and voice work. Shared components need light/dark, keyboard, touch and small-viewport regression checks.
4. Record the exact commit, deployed ID, installed build numbers, test track, operating system and observed result. Resolve the branch protection and owner-console gates before public expansion.
