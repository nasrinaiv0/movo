# MOVO full audit — November 21, 2026

MOVO is **not ready for a production or App Store release**. This audit reproduced and fixes eight issues in the #330 candidate, including a cross-account backup restore race and financial import errors. Production hosting, the remaining ownership/erasure rollout, signed-device acceptance and store identity/rights evidence are still open gates. The application architecture, financial fields, account identifiers, API contracts and historical records are preserved.

This is a source, automated regression, isolated browser and read-only production-catalog audit. It is not a penetration-test certificate, a legal opinion, Apple approval, or proof that every device, provider and authenticated journey works.

## Reproduced defects and implemented resolutions

Severity describes the pre-fix behavior. “Fixed” here means the candidate source and stated regression pass, not that production received it.

| ID | Severity | Trigger and consequence | Candidate resolution and evidence |
| --- | --- | --- | --- |
| A1 | High | Pause backup restoration on an asynchronous receipt write, then switch accounts. The old action could resume, expose the old financial rows in the active view and restore unrelated artwork. | `App.js` binds the action to its rendered owner and session generation; checks run before work and after receipt, QR and hybrid-storage awaits, before visible records or extras are applied. Guest→B and A→B regressions plus stale-action rejection pass in `AppPreferenceIsolation.test.js`. Data already committed to the explicitly captured original owner's storage is not reassigned or destructively rolled back. |
| A2 | High | A generic file import names two existing accounts with the same normalized name, or names an absent account. `planImport` selected the first match or silently used `local`, including ambiguous transfer destinations. | Reuse the existing unique-account resolver; skip an explicitly named unresolved/ambiguous source or destination as a conflict. The existing no-label compatibility behavior remains. Regression proves that only the uniquely matched account receives a record. Identifier-aware MOVO backup routing remains in its existing restore planner. |
| A3 | Medium | Import `1.005` or `-1.005`, an unsafe cent-sized amount, or an explicitly invalid balance. Different parsers used binary `Math.round` and invalid account balances could become zero. | CSV/JSON use canonical symmetric `roundMoney`, reject unsafe cent amounts and rounded-zero CSV postings, and reject explicitly invalid account balances/saved-goal amounts. Missing optional balances still default as before. `1.005` becomes `1.01`; `-1.005` becomes `-1.01`. No historical values are rewritten. |
| A4 | Medium | JSON date `2026-02-30`, an ISO timestamp with that day, or numeric US date `02/30/2026` rolls into March. Invalid optional deadlines could become a different date or today's renewal. | Shared calendar validation rejects rollover before timestamp parsing. Supplied invalid renewal/deadline/due dates cause the affected row to be skipped; omitted optional dates keep existing defaults. Leap-day and invalid-date regressions pass. Other supported legacy date formats retain their existing parsing compatibility; use ISO dates for unambiguous interchange. |
| A5 | Medium | `sumMoney([10, NaN])` returned 10; unsafe postings could disappear, and an intermediate overflow could lose precision before cancellation. | Invalid/unsafe cents and unsafe intermediate sums propagate `NaN` rather than producing a plausible partial total. Existing valid cent arithmetic and transfer direction are unchanged. |
| A6 | Medium | Five fixed font/icon columns squeezed English words into fragments at 320px and 130% text size. | Append an `auto-fit` grid rule with a text-relative minimum to `Settings.css`; choices reflow with the panel and text size. Fresh small-screen/dark/desktop captures and geometry checks verify the result. No screen or choice is removed. |
| A7 | Low | The tablet/desktop Home activity badge contributed “New activity” to the button's accessible name; the name changed with unread state. | Side navigation now uses the same translated explicit accessible label as phone navigation. Visible badge/state and existing navigation remain. |
| A8 | Medium, release tooling | Hosted paired R8 run `44867343356` built both compiler comparisons, then failed at `adb root` with `unable to connect for root: closed`, before instrumentation. | Recover only recognized transport disconnects, at most three attempts, pinned to the same previously verified disposable emulator. Recheck emulator identity and require UID 0. Unknown errors/timeouts remain hard failures; network isolation and exact instrumentation success assertions remain. All 23 harness unit tests pass; a new hosted paired run is still required. |

The import/cent/calendar regressions first produced **7 failing tests**, and the delayed-restore regression independently reproduced a completed save after an account switch. They pass with the fixes. This gives behavioral evidence beyond a source-only claim.

## Security and accounting observations

The [catalog evidence](assets/2026-11-21-full-audit/database-evidence.json) records **53 public tables, all with RLS enabled**. Anonymous users cannot insert transactions; authenticated direct UPDATE/DELETE remain revoked. Authenticated INSERT is intentional compatibility behavior protected by owner RLS, account-owner foreign keys and the existing plan/reconciliation triggers. Do not revoke it blindly or add permissive policies just to silence an advisor.

Fifteen authenticated-executable security-definer functions are advisor warnings requiring authorization review, not fifteen demonstrated exploits. All fifteen deny anonymous execution; search paths are fixed, and anon/authenticated roles cannot create in `public`. Read-only inspection of sync, payment, loan, restore and plan-guard definitions found explicit identity/owner checks. The existing finance tenant-isolation and IAP SQL workflows passed at `f2aa4587`; fresh commit runs remain necessary. No claim is made that catalog inspection alone proves every function safe.

Twenty-four “RLS enabled, no policy” informational notices include backend-only tables and represent default denial. Thirty-seven unused-index notices are informational; no ownership or foreign-key index was dropped based on limited production usage. See [RLS advisor](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [definer advisor](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) and [index advisor](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index).

The latest deployed accounting migration remains `20261120025027 harden_transaction_mutations_and_posted_allocations`. Reversal, allocation, pending/posted, transfer, debt/card and FX behavior are covered by the existing regression/SQL suites. This audit does not reconcile historical customer ledgers or certify every external exchange rate. No customer record was inspected or changed.

## Verification and disposition

Local verification on Node 26.13.1: **258 Jest suites / 1,704 tests**, typecheck, **24 Node tests**, **23 Python harness tests**, strict app-store-profile build with 54 worker resources and packaging audit, and a normal strict web build. The final style adjustment is covered by the final app-store strict build/browser reflow check; the normal strict web build preceded only that stylesheet adjustment. No functional JavaScript changed after the full suite. Existing non-fatal React `act` warnings were observed; test failures were not suppressed.

At `f2aa4587`, seven hosted workflows passed (web, hybrid security/accounting, finance SQL, IAP SQL, iOS, Android, Cloud Run container); the eighth, paired R8, failed at ADB startup. Those outcomes are historical for the newly remediated source. Fresh exact-head CI is required and is recorded in #330. SQL was not rerun locally because this execution environment has no PostgreSQL client/server; hosted isolation tests use disposable databases.

Keep #330/#331/#291/#274 as separate reviewable work. Do not merge on an old green SHA, a canceled check, or an unaccepted migration/device/store gate. No PR was merged and no production action was taken during this audit. Recommended order: land verified owner/import safeguards with accepted hosting, integrate them into encryption/erasure clients, approve and validate the remaining production migrations, complete signed-device/backend and store evidence, then release with rollback and monitored verification.
